# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Les Secrets de Cassis": a mobile web treasure-hunt game, one phone per team, with a live organiser dashboard. Plain HTML + vanilla JS, **no dependencies, no build step**. Hosted as static files on GitHub Pages. UI text, comments and docs are in French: keep them that way.

## Commands

- Run all tests: `node --test test/engine.test.js` (Node 22 rejects a bare directory like `test/`)
- Run one test: `node --test --test-name-pattern="normalisation" test/engine.test.js`
- Several tests load the real `contenu.js` and check its zone ids (e.g. `zones[2].A[0]` answers "Eglise Saint-Michel", circuit of team E6). Editing the demo content can break them.
- Regenerate the publishable `game.js` from `contenu.js` (validates first, exits 1 on errors): `node outils/publier.js`
- Run locally: open `index.html` directly (`file://`) or serve on localhost. Add `?equipe=E1` to play as a team, `?reset` to wipe local progress.

## Architecture

**Two content files, one secret.**
- `contenu.js` sets `window.GAME_SOURCE`: teams, circuits, puzzles, **answers and codes in plain text**. Git-ignored; must never be published. Its header comment documents the step types and fields.
- `game.js` sets `window.GAME`: generated by `Engine.publishedFile()` (via `outils/publier.js` or the download button in `outils.html`). Answers become `step.h` hashes; `masterCode`/`adminCode` become `masterHash`/`adminHash`. It also holds `answerBook`: the plain answers + `masterCode`, AES-GCM encrypted with a PBKDF2 key from `adminCode` (Web Crypto, so `publishedFile` is async), decrypted by the dashboard's « Réponses » view. Never edit by hand; regenerate after every change to `contenu.js`.
- `index.html` and `admin.html` load `game.js`, then inject `contenu.js` via `document.write` only on `file:`/localhost. Code reads `window.GAME_SOURCE || window.GAME`, so every check must work with both plain values and hashes (see `checkAnswer`/`answerHashes` and `codeMatches(input, plain, hashed, salt)`).
- Hashing is cyrb53 (sync, works on `file://`). It obfuscates answers and is not real security; puzzle text stays readable in `game.js`.

**`js/engine.js`: pure logic, no DOM.** It is a UMD module (`window.Engine` in the browser, `require` in Node), shared by the game, the dashboard, the tools page, the tests and `publier.js`. Put any testable logic here: answer normalisation (case/accents/punctuation ignored, `ST`→`SAINT`, `match: 'contains'` tries every contiguous word sequence), `buildPath` (flattens a team's circuit into steps with `key = z{zone}-{variant}-{i}`, then appends `final`), penalties/timing, GPS distance, `tap` hit-testing, badges, ranking, `validate`, `simulate` (zone occupancy per slot), `publish`.

**Game model.** `zones[id]` holds variants `A`/`B`, each a list of steps. A team has a `circuit` (ordered zone ids) and a `variant` (string, or a per-zone object). The first step of each zone is the riddle that leads *to* that zone, so any circuit order works. Tests assume that for the demo content no zone ever has more than 2 teams in a slot, and that teams sharing a slot use different variants.

**Front-ends** (each one is an IIFE that renders HTML strings into a root element):
- `js/app.js` (player): state is kept in `localStorage` under `escape:{GAME.id}` and synced to other tabs through the `storage` event (a scanned checkpoint QR opens a new tab with `?scan=`). Pushes are debounced to Supabase, plus a 30 s heartbeat. Works offline. If a phone dies, another phone can resume the team from its server row.
- `js/admin.js` (dashboard): code-gated (`adminCode`/`adminHash`), polls Supabase every 10 s, flags stuck teams, and warns if `contenu.js` is reachable on the deployed site.
- `js/outils.js` (prep tools, loads `contenu.js` directly): validation, circuit simulation, `game.js` download, printable QR codes generated locally by `js/qrcode.js` (self-contained encoder, byte mode, EC level M, versions 1-10).
- `js/sync.js`: Supabase REST calls through raw `fetch` (no client lib) on a single `progress` table (`team` PK, `data` jsonb). Disabled when `config.js` has empty `supabase.url`/`key`. The schema and anon RLS policies live in `supabase.sql`. Keys starting with `eyJ` (legacy anon JWT) also get sent as `Authorization: Bearer`.

`config.js` contains only public values (`publicUrl` used for QR codes, Supabase URL + publishable key).
